# Экспериментальный анализ Stooge Sort

## 📌 Описание проекта

В рамках данного проекта проводится теоретический и экспериментальный анализ алгоритма сортировки **Stooge Sort** — намеренно неэффективного рекурсивного алгоритма, используемого в учебных целях.

Основная задача:

* сравнить теоретическую модель,
* точную дискретную оценку,
* и результаты экспериментальных измерений.

---

## Сама сортировка (чтобы не потерялись в файлах - находится в StoogeSort.java):
    public static void stoogeSort(int[] arr, int l, int h) // Массив, левый указатель, правый указатель
    {
        // Если левый указатель больше правого, останавливаемся
        if (l >= h)
            return;

        // Если первый элемент меньше последнего, меняем их местами
        if (arr[l] > arr[h]) {
            int t = arr[l];
            arr[l] = arr[h];
            arr[h] = t;
        }

        // Если в массиве больше 2-ух элементов, то:
        if (h - l + 1 > 2) {
            // находим сколько элементов является 1/3
            int t = (h - l + 1) / 3;

            // Рекурсивно сортируем первую 2/3 часть
            stoogeSort(arr, l, h - t); // Вычитаем из правого указателя 1/3

            // Рекурсивно сортируем вторую 2/3 часть
            stoogeSort(arr, l + t, h); // Добавляем к левому указателю 1/3

            // Рекурсивно сортируем первую 2/3 часть
            // Убеждаемся, что всё отсортировано
            stoogeSort(arr, l, h - t);
        }
    }


## 📁 Структура проекта

Проект состоит из следующих основных компонентов:

### 🔹 Генерация и чтение данных

* **DataGenerator**
  Генерирует входные массивы различных типов:

    * случайные
    * отсортированные
    * обратные
    * почти отсортированные

  Данные сохраняются в папку `data`.

* **DataReader**
  Загружает массив из текстового файла для последующей обработки.

---

### 🔹 Конфигурация эксперимента

* **ExperimentConfig**
  Содержит параметры эксперимента:

    * диапазон размеров входа
    * шаг изменения размера
    * количество прогревов (warmup)
    * количество измерений
    * типы входных данных

---

### 🔹 Алгоритм сортировки

* **StoogeSort**
  Реализация алгоритма Stooge Sort:

    * стандартная версия сортировки
    * версия с подсчётом метрик (рекурсивные вызовы и swap’ы)

* **SortMetrics**
  Хранит метрики выполнения:

    * число рекурсивных вызовов
    * число обменов
    * общее число операций

---

### 🔹 Запуск эксперимента

* **Runner**
  Основной класс для проведения эксперимента:

    * загружает данные
    * запускает сортировку
    * измеряет время и метрики
    * собирает результаты

* **Result**
  Модель данных для хранения результата одного эксперимента:

    * размер массива
    * тип данных
    * время выполнения
    * метрики операций

---

### 🔹 Теоретическая модель

* **TheoryEstimator**
  Реализует два подхода к оценке сложности:

    * `exactCallCount(n)`
      Точная дискретная модель количества рекурсивных вызовов:
      учитывает целочисленное деление (`floor(n / 3)`), полностью совпадает с реализацией алгоритма.

    * `smoothApproximation(n)`
      Сглаженная асимптотическая оценка вида:
      k · n^2.7095

      Используется для визуального сравнения с теорией без учёта дискретных эффектов.

---

### 🔹 Экспорт результатов

* **ExcelExporter**
  Сохраняет результаты экспериментов в файл `results.xlsx`, включая:

    * таблицу измерений
    * параметры эксперимента
    * теоретические оценки
    * агрегированные метрики

---

### 🔹 Точка входа

* **Main**
  Используется для:

    * тестирования сортировки
    * запуска полного эксперимента (через Runner)


## 🧠 О алгоритме

Stooge Sort задаётся рекуррентным соотношением:

T(n) = 3T(2n/3) + O(1)

Отсюда асимптотическая сложность:

O(n^log_{3/2}(3)) ≈ O(n^2.7095)

Алгоритм не используется на практике из-за высокой сложности, но хорошо подходит для:

* изучения рекурсии,
* анализа рекуррентных соотношений,
* демонстрации различий между теорией и экспериментом.

## 📊 Измеряемые метрики

В рамках эксперимента фиксируются:

* время выполнения (усреднение по нескольким запускам)
* число рекурсивных вызовов
* число обменов (swap)
* общее число операций (calls + swaps)

## 🔍 Ключевые наблюдения

### 1. Детерминированность

Количество рекурсивных вызовов полностью определяется размером входа.

В результате:

* теоретическая модель (рекуррентная формула)
* и экспериментальные данные

практически совпадают.

---

### 2. Дискретный характер роста

Из-за целочисленного деления:

t = floor(n / 3)

рекурсивная структура остаётся одинаковой на целых интервалах значений n.

Это приводит к:

* “ступенчатому” росту числа операций
* наличию плато на графиках

---

### 3. Использование аппроксимации

В работе используется функция вида:

k · n^2.7095

которая представляет собой **сглаженную асимптотическую модель**.

Аппроксимация применяется как визуальный ориентир и позволяет сравнить:

* непрерывную теоретическую оценку (без учёта целочисленного деления),
* и дискретную реализацию алгоритма, где используется `floor(n / 3)`.

Причины использования:

* асимптотика задаёт форму роста, но не учитывает дискретную природу алгоритма;
* в реализации размеры подзадач округляются, что приводит к “ступенчатому” поведению;
* аппроксимация позволяет увидеть, как выглядел бы рост без этих эффектов.

Важно:

* для числа операций используется **точная дискретная модель** (`exactCallCount`);
* аппроксимация **не заменяет теорию**, а служит для наглядного сравнения;
* основная ценность — показать различие между гладкой асимптотикой и реальным поведением алгоритма.

## 📈 Результаты

* время выполнения растёт примерно как O(n^2.7)
* число операций строго следует теоретической модели
* тип входных данных слабо влияет на общее число операций
* основную нагрузку создаёт рекурсивная структура, а не swap’ы

## 🎯 Вывод

Stooge Sort не имеет практической ценности как алгоритм сортировки, однако является удобным инструментом для:

* демонстрации рекурсии
* анализа асимптотики
* изучения различий между дискретной моделью и гладкими оценками

Проект показывает, что:

* теория и эксперимент могут совпадать (для числа операций)
* при этом поведение остаётся дискретным и “ступенчатым”
